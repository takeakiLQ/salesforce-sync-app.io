# スプレッドシート連携仕様（アプリ開発者向け）

Salesforce 同期ツール（`salesforce_sync_Ver2`）が書き込む Google スプレッドシートを
アプリから読む際の仕様です。2026-07-30 時点。

対象ブック：**`Salesforce連携_Ver2`**
（ID `1doCWi9cQ5tv1GR4BRm1_IlTwbEVeu4oQwARjtyNb00Q`）

---

## 1. 同期のタイミング

| 項目 | 内容 |
|---|---|
| 実行時刻 | **毎日 0:00 / 8:00 / 12:00 / 16:00 / 20:00**（5回） |
| 所要時間 | 約 **3分**（実測 2分40秒〜3分30秒） |
| 更新されるシート | 稼働中案件 / パートナー情報 / 案件_FY2025 / 離脱パートナー |

※ 0:00〜8:00 が8時間空いているのは意図的です（この時間帯は Salesforce 側の更新がほぼ無い）。

---

## 2. ★重要：同期中はシートが一時的に空になります

同期は各シートを **全消去 → 全件書き込み** する方式のため、
**その間シートが空（ヘッダーも含めて0行）になる瞬間があります。**

実測した「空になる時間」：

| シート | 空になる時間 |
|---|---|
| 案件_FY2025 | 7.9 秒 |
| パートナー情報 | 4.3 秒 |
| 稼働中案件 | 6.6 秒 |
| **離脱パートナー** | **16.3 秒**（最長） |

1日あたり合計で約175秒（24時間の 0.2%）。**500回読んで1回程度当たる確率**です。

### お願いしたい実装

**取得結果が0件だった場合は「同期中」と判断し、リトライしてください。**

```
推奨：5秒待って最大3回リトライ（最長16.3秒をカバーできます）
```

3回とも0件なら本当の異常として扱ってください。

> なぜ「空にならない方式」にしないのか
> 「上書きしてから余った行を削る」方式に変えると空にはなりませんが、
> 代わりに **「上半分が新しいデータ・下半分が古いデータ」という混在状態** が
> 発生します。空なら一目で異常と分かりますが、混在は正常に見えて中身が
> 不整合なので、参照用DBとしてはより危険と判断しました。
> **「空になる」＝「今は読まないで」の明確なシグナル**として使ってください。

## 3. ★新設：`更新日時` シート（データの鮮度確認用）

各シートが最後に更新された日時を記録しています。**利用者に「データがいつ時点のものか」を
見せる目的で作りました。**

### 列の仕様（★この順序と意味は変更しません）

| 列 | 項目 | 内容 |
|---|---|---|
| A | シート名 | 対象シートの名前 |
| B | 最終更新日時 | `YYYY-MM-DD HH:MM:SS` 形式 |
| C | 件数 | そのシートのデータ行数（ヘッダーを除く） |
| D | 状態 | `OK` または `NG` |
| E | 所要秒 | そのシートの処理にかかった秒数 |

- 2行目以降にデータ。**シート名の昇順**で並びます
- 現在の行数は4行（更新対象の4シート分）

### 表示例

```
シート名          最終更新日時          件数     状態  所要秒
パートナー情報     2026-07-30 16:46:12  3959    OK   49.5
案件_FY2025       2026-07-30 16:44:03  9097    OK   15.4
稼働中案件         2026-07-30 16:45:38  5404    OK   50.0
離脱パートナー      2026-07-30 16:46:40  13432   OK   40.0
```

### ★解釈で注意していただきたい点

**「最終更新日時」は、そのシートに実際に書き込めた最後の時刻です。**

同期が失敗した場合、**日時は進みません。前回成功した時刻のまま据え置かれ、状態が `NG` になります。**

```
パートナー情報   2026-07-30 16:11:52   3959   NG   5.7
                 ↑ 16:11 のデータのまま  ↑ 直近の同期は失敗
```

つまりこう読んでください。

| 状態 | 意味 | 利用者への表示例 |
|---|---|---|
| `OK` | 最後の同期が成功。**日時＝データの時点** | 「2026-07-30 16:46 時点」 |
| `NG` | 直近の同期が失敗。**日時は前回成功時のもの** | 「2026-07-30 16:11 時点（更新に失敗しています）」 |

**`NG` かつ日時が古い場合、利用者に警告を出していただけると理想的です。**
同期側でも Slack に通知し、10時間更新が無ければ死活監視が警報を出しますが、
**利用者が画面上で気づけることが最後の砦**になります。

### 補足

- **無効化中のシート**（`案件_FY2018_FY2020` / `案件_FY2019_FY2024`）は行がありません。
  これらは過去データで内容が変わらないため意図的に同期対象外にしています
  （最終更新は 2025-09 頃で固定）
- このシートも同期の最後に書き換えられます。**アプリから書き込まないでください**

## 5. 列レイアウトについて

**同期ツール側で列の増減・並べ替えは行いません。**
アプリが列位置を前提にしていると伺ったため、以下も含めて現状維持とします。

- Salesforce のリレーション項目展開で生じる `〜.attributes.type` / `〜.attributes.url` 等の
  一見不要な列（`Partner__r.attributes.type` など）
- 計算列の手前にある空き列（`稼働中案件` の AF〜AZ、`パートナー情報` の AK〜AV）

**もし列レイアウトの変更が必要になった場合は、事前に相談させてください。**
逆に、SOQL の項目追加でデータ列が計算列に侵入しそうな場合は同期側で検知して
書き込みを中止するガードを入れてあるので、**気づかないうちに列がずれることはありません。**

| パートナー情報 | BA〜HL | 曜日×時間の稼働フラグ 168列（稼働中案件から集約） |
| 離脱パートナー | 末尾2列 | 最終稼働日 / 最終案件名 |

### 稼働フラグの仕様（2026-07-30 修正）

- **日を跨ぐ勤務は翌曜日にもフラグが立ちます。**
  例）月曜 18:00〜翌06:00 → `月_18`〜`月_23` ＋ `火_00`〜`火_05`
- 終了時刻が `00:00` の場合は「その日の24:00」として扱い、翌日には立てません。
  例）月曜 19:00〜00:00 → `月_19`〜`月_23` のみ
- 開始と終了が同じ時刻の場合は「1時間の勤務」として扱います。
  例）01:00〜01:00 → `月_01`

**修正前は日跨ぎ勤務35件のフラグが全て0（稼働なし）になっていました。**
夜勤のパートナーが「稼働なし」と表示されていたため、修正後は表示が変わります。
